# Rebuttal Craft

把每条审稿意见变成可核查、易浏览的回答。面向 reviewer 解答具体疑问，同时让 AC 能快速看到结论与证据。先回答问题，再解释依据；不把“争取提分”当成已验证结论，也不保证 rebuttal 能改变分数。

这是写作方法，不替代项目的证据流程、会议规则或作者的阶段授权。只准备环境时，不自动分析意见、制定实验或起草回复；只修改指定回复时，不扩写其他部分。

## 开始前确定输入

读取本次所需的审稿原文、实际投稿版本和作者提供的证据。保留 reviewer ID、问题原文及对应位置；综合摘要不能替代原文。按明确的会议、年份、track 核对与当前输出有关的格式、字数/字符数、轮次和截止时间；未核实时写明待核实，不套用截图中的 NeurIPS 经验作为 ICLR 规则。

遵循项目已经建立的取证路径。如果项目要求多服务器搜索，先查询全部指定服务器，逐机记录范围、时间与访问失败，再判断材料是否缺失。只在本机没找到，不能写成“没有这项结果”。研究数据、凭据和私有评审原文不进入可公开的 skill。

## 把意见拆成可回答的问题

保留每条原始意见的来源，按独立请求拆分并稳定编号，例如 `R2-Q3`。一句话有多个独立问题可以拆开；同一问题的解释与例子不要机械拆成多条。按实际问题选择澄清、补充已有证据、承认并修正、有限度反驳或提出待验证实验，不预设审稿人误解。

作者需要分析时，用单独工作表连接“原文 → 问题 → 回答结论 → 证据 → 稿件改动 → 未决事项”。不要把内部分类、优先级、服务器路径或检查过程粘进 reviewer-facing 回复。

## 写好开头

- 若该 reviewer 确实认可了具体优点，用一句简短感谢准确复述。不得虚构正面评价，也不要拿另一位 reviewer 的表扬说服当前 reviewer。
- 总领句只覆盖实际回答并有依据的事项，例如“Below we clarify the construction and report the available matched comparison.” 避免无证据声称“所有问题都源于误解”“已全部解决”。
- 在字数有限或单个 follow-up 中，可以直接回答，不强制寒暄、赞美或总领段。

## 每一点先给结论，再给证据

采用 BLUF（Bottom Line Up Front）方式：每个要点用一个简短的**加粗结论句**开头，随后给解释、证据与必要边界。每点只负责一个中心结论；同一 concern 可以用多个互补要点回答。

优先保持这个信息顺序，按问题需要裁剪，不机械凑齐四段：

1. **直接回答**审稿人的疑问，能给明确事实时不要先铺垫。
2. **解释机制或歧义**，说明实际做法、定义或比较条件。
3. **提供可核实依据**，用投稿稿件位置、已完成实验、原始记录、核实的文献或成立条件明确的推理支撑。
4. **交代修正或边界**，准确区分已修改、拟修改与尚未验证。

只有对回答有帮助的角度才保留。澄清、换一种解释、额外结果与承认限制可以互补，但不要重复同一个论点，也不要用礼貌话挤占实质回答。

格式示例（占位符不是事实，不能直接提交）：

```markdown
**R2-Q3 — [具体问题]**

- **[直接回答该问题的结论。]** [机制解释及已核实的证据或稿件定位。]
- **[另一项必要结论。]** [互补证据，并写清比较条件或限制。]

[如有必要，说明已完成的改动或明确标为计划的修订。]
```

## 让证据和语气匹配

- 有效批评就承认具体缺口并说明可落实的修正；有依据的分歧就解释前提、比较条件或证据。避免空泛的“We disagree”、情绪化用词和揣测动机。
- 未运行的实验只写为计划；正在运行的实验不写为结果；旧结果、探索性结果、未匹配预算与正式验证明确区分。
- 数值回到实际表格、summary 或原始记录；引用回到已核实来源。来源缺失时收窄主张或列入待核实项，不补造结果或引用。
- 保留反结果、失败及科学限制。单 seed、重叠区间、零命中或代理指标不能自动支撑稳定性、等价性、零风险或整体质量结论。
- 承诺只覆盖作者实际允许且可完成的修改。不把“将补充实验”写成“实验已证明”。
- 按项目和平台的访问/互盲约束组织回复；不要向当前 reviewer 泄露其他 reviewer 的原文、分数、编号或回复。跨 reviewer 的内部综合与面向 AC 的材料单独准备，并遵守当年平台规则。

## 为快速阅读整理格式

平台支持时使用 Markdown、稳定问题编号及短段落。表格只用于确有比较价值的数据；不要为了排版丢掉预算、样本量、单位或限定条件。按平台实际计数方式检查上限，保留公式、引文与 reviewer 原文的含义。

压缩时先删重复感谢、泛泛价值宣言、同义重复与无关背景，再压缩解释。保留直接回答、决定性证据、关键条件和真实限制。作者指定结构或选区优先，不为套此模板重写范围外文字。

## 交付前检查

逐项确认问题已回答或明确标成未决，结论能在证据中定位，修改状态与承诺准确，语气平和且不推卸责任，格式和计数符合已核实规则。只报告实际执行的检查。

默认交付作者要求的回复文本；证据缺口与待验证事项放在单独短注中。没有明确授权，不启动实验、不改队列、不发邮件、不把内容提交到 OpenReview 或其他外部平台。
