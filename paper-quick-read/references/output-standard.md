# 五部分论文讲解规范

确认日期：2026-10-31。篇幅与信息组织参照用户认可的 STAR 讲解；完整示例见 [star-example.md](star-example.md)。

## 1. 定位、语言与篇幅

让读者能复述“为什么做、具体怎么做、证据支持什么、还有什么没解决”，并判断是否需要精读。专业但直白，先直觉后形式化，保留关键英文术语；不逐段翻译，也不把摘要改写成五段。

默认约 3,000–5,000 个中文正文汉字，公式、Mermaid、表格、代码、英文术语与引用另计。STAR 示例约 3,790 个汉字，含公式与图表语法的原始 Markdown 约 9,181 字符，可用于校准尺度。字数是软目标，不为达标注水，不需要向读者报告计数。

| 部分 | 汉字软目标 | 详略与作用 |
| --- | ---: | --- |
| 开头与论文身份 | 100–200 | 一句话核心思想，随后核实身份、版本与发表情况 |
| Insight & Motivation | 300–500 | 用一个例子解释问题、现有缺口与关键观察 |
| Method | 1,500–2,400 | 最详，约占解释篇幅 45%–55%；复杂机制可增加 |
| Experiments | 500–800 | 配置、直接比较、消融、定性与效率证据 |
| Limitations | 450–700 | 通常 3–5 项，解释原因、条件与证据缺口 |
| 对你研究的启发 | 350–600 | 借鉴思想及 2–3 个可检验方向 |

简单论文可短，公式密集论文可长。用户要求“简短/五分钟版”时可约 800–1,500 汉字并保留主线；要求更细时扩展真正有难度的部分。用户只问一个概念、模块或公式时直接回答，不重跑全文模板。非典型论文（理论、综述、数据集或系统）按真实贡献调整对应内容，不虚构训练损失或实验。

## 2. 开头与 Insight & Motivation

开头第一句话解释方法改变了什么、解决什么具体问题。接着简洁给出规范标题、原文链接、正式发表与预印本时间、实际阅读版本。作者、单位、代码仅在核实且有用时列出；不从作者现职、商标或聚合页推断单位。不默认堆排名、影响因子或长作者名单。

动机按“现有流程 → 具体失效环节 → 一个可贯穿方法的例子 → 作者观察/假设 → 新设计”组织。交代任务输入输出，区分事实、作者主张与自己的机制解释。可以用图表诊断问题，但不能把待验证假设先写成已证实原因。

## 3. Method：整体框架先行

### 3.1 流程图

在细节和公式之前，先用一小段话定位改动，再呈现一张忠实原文的概括流程图。

- 支持 Mermaid 时优先使用 Mermaid；宿主不能渲染时改用箭头框图或编号支路，不能把不能渲染的代码充当已呈现的图。
- 一般 6–10 个节点，通常不超过 12 个。窄屏优先 TD；简短且自然的横向流程可用 LR。
- 包含输入、主要计算、中间信号及目标/输出；存在并行支路时标出汇合点。
- 训练和推理不同要标清，旧策略、冻结参考、奖励模型等角色不要混用。
- 自行简化重构时说明“根据原文简化”，不冒充作者原图，不虚构原文没有的模块。
- 用节点与箭头表达计算关系；避免装饰节点、满屏公式或实现参数。

后文步骤必须对应图中的真实模块和数据流。图负责导航，不能画一套流程而另讲一套。

### 3.2 分步解释

按执行顺序拆成通常 4–8 步，复杂方法以需要为准。每一步回答：输入来自哪里、具体计算什么、输出交给谁、为何针对动机中的问题、它是基线已有还是本文新增。

尽量沿用动机里的例子。对归一化、符号、权重范围、概率比等容易误解的变换，使用少量数值帮助理解；标记为教学示例并核对算术，不混成论文结果。

### 3.3 公式讲解

只选理解所需的核心公式，不机械照抄全文。一般 3–7 组，复杂方法可增加；相关中间式可合并为一组。每组按以下顺序解释：

1. **目的**：为什么需要此式、它解决什么问题。
2. **公式**：正确 LaTeX，必要时附原文公式号。
3. **符号**：首次出现的上下标、集合、分布、变量与超参数逐项说明，需要时给维度。
4. **直觉**：各项如何一起计算，与上一步输出如何衔接。
5. **方向**：最大化/最小化时鼓励什么；非优化式说明取值范围与变换行为。
6. **实现和假设**：采样分布、冻结、停止梯度、近似、归一化等如何影响结果。

公式放在普通正文的行内数学或独立数学块，不放引用块或以反引号包数学符号。重写记号、合并公式或推导新表达时，说明是等价改写、通用背景或自己的推导，不编造原文公式号。

### 3.4 单独拆开真正易错的设计

从本篇论文选 1–3 个关键误读风险，不机械套用 STAR 的专属问题。例如：

- stop-gradient 的前向值与反向梯度有何区别？不能代数抵消后认定没有梯度。
- 权重改变强度还是方向？是否保持正负号？是否归一化到总和/均值为 1？是否改变整体更新规模？
- 优势、概率比、裁剪和损失在哪个粒度计算？局部梯度不等于独立局部 ratio。
- 信号代表语义相关性、奖励敏感性、局部好坏，还是因果贡献？作者实际估计的是哪一个？
- 正文的通用概念与附录的默认实现是否不同？哪些步骤只是可选变体？

讲清训练时采样、更新及冻结对象；交代推理是否仍需辅助模块或额外计算。未报告的设置直接说明缺失，不用常见默认值替作者补写。

只有有助于区分机制时才给小型相关方法表，一般本文加 1–2 个最相近方法，比较信号来源、粒度、更新方式、成本与任务，不罗列论文名。

## 4. Experiments：数值服务于判断

通常覆盖以下层次，按论文内容组织：

- **设置**：任务、数据与划分（已报告时）、骨干、奖励、训练方式、关键超参数、评估配置与直接基线；选择影响公平性和复现的信息，必要时给配置表。
- **主结果**：优先同骨干同奖励条件的比较，采用“基线 → 本文 → 变化”的小表；写清指标方向、分数含义及绝对/相对变化。区分百分比、百分点和原始分数。
- **消融**：改变什么、控制什么、观察什么、支持哪个设计判断；读曲线时解释横纵轴、趋势及不确定性，不编造无法精确读出的数字。
- **定性与开销**：提取 1–2 个有解释价值的行为或视觉模式，说明比较对象与缺失控制；报告资源指标的测量范围。

至少解释一项主结果及一项消融/机制证据；论文没有相应实验时明确缺失，不能虚构。引用有用的图表编号与页/节位置，但聊天默认不插“待手动插图”占位符或建图库。

保留退步、失败与指标冲突。训练奖励不同于独立评估；多任务各自的分数不能当成一个 checkpoint 的联合能力。基座对整套后训练的比较不能全部归因于新增模块；少量展示图不能替代统计证据。论文没有硬件、数据规模、种子或优化器等信息时据实说明，不编造。

## 5. Limitations：有理由的独立判断

通常 3–5 项，复杂论文可更多。先交代作者有没有明确局限陈述，自己的分析明确标记。每项尽量包含“哪里受限 → 为何产生 → 什么场景暴露 → 现有实验是否检验”。

检查关键假设、代理信号可靠性、局部与全局冲突、监督粒度、计算成本、泛化、评估与复现信息。由公式提出的机制疑点是待排除的解释，不能直接写成作者已失败；缺少实验是证据缺口，不是已证实的失效。

## 6. 对你研究的启发

结合已知且相关的研究上下文；没有依据时使用一般研究问题，不编造读者的项目，也不把其曾讨论的主题视为永久主题。

先解释 1–2 条可借鉴的研究思想及成立条件，再给 2–3 个延伸，每个至少有清楚的问题/假设及最小验证方法；必要时加对照与指标。适合时用“研究问题｜最小验证方式”表格，优先回应局限中已经指出的机制疑点。

延伸明确标为自己的设想。不自动启动大规模查新，不把未检索的想法称为新颖或可发表，也不承诺论文尚未验证的结果。

## 7. 交付前自检

- 开头直接解释核心思想，五部分顺序正确，Method 最详；窄问题依当次范围回答。
- 方法图已呈现且与正文顺序一致，输入输出、训练/推理及各模型角色准确。
- 公式的目的、符号、计算、方向与实现假设讲清；小例子算术正确。
- 正文与附录的实际实现已核对，基线与新增设计、相关与因果、全局与局部没有混淆。
- 主结果有数值与直接对照，消融不过度解释，退步及缺失证据保留。
- 事实、自己的推导、分析和设想可区分；引用靠近对应论点。
- 没有虚构元信息、代码地址、实验细节、图表或读者背景。
- 不默认创建外部笔记，不套逐段译文或十三节笔记，不用字数目标制造冗余。
